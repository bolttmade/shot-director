# examples/real: REAL model outputs

This folder holds **real** clips (generated by a model, not by `app/vcam.py`), all made on 2026-10-16, each with its own `.json` notes (model, prompt, credits, request id, honest verdict) and `.recipe.json`:

| Kind | Files | What they are |
|---|---|---|
| LTX-2.3 (Comfy Cloud web UI, free tier) | `alley__dolly-in.mp4`, `alley__crane-up.mp4` | Prompt-only, no camera LoRA, unedited. The crane clip is partial (rises but also pushes forward). |
| MiniMax H3 via the Comfy Router (5 clips) | `*__router-minimax-h3.mp4` | 768P, 5 s, 135.78 credits each. Own ratings 7-8/10. Best: `forest-cabin__fpv-drone__router-minimax-h3.mp4` and `forest-cabin__dolly-in__router-minimax-h3.mp4` (8/10). |
| Grok Imagine 1.5 lite via the Router (6 clips) | `*__router-grok-imagine-1-5-lite*.mp4` | 5 s, 30-48 credits each (the cheap tier). Ratings 6-7/10. |
| FLUX 3 Video via the Router (1 clip) | `retro-diner__arc__router-flux-3-video.mp4` | 5 s, 226.3 credits. Clean but barely moves (4/10): kept as an honest data point. |
| FLUX 3 Image via the Router (6 stills) | `coverage/alley/coverage-*.jpg` | Angle re-shoots of the alley still, 86.9 credits. Replayed by the Demo engine's coverage board. |

The Router clips are **partner models: not open weights, not LTX, prompt-only (no camera LoRA), unedited** (the importer only strips metadata and, for files wider than 1280 px, re-encodes at 1280 wide). The extra `__router-...` name part makes each a gallery-only variant: the Demo engine never uses them in place of the LTX clips. The camera-move accuracy differs a lot between models, which is exactly the point of the gallery. Everything else under `examples/` is a labelled simulation (see `../CREDITS.md`); the totals and request ids are in `../../docs/COSTS.md`.

## What to drop here

| File | Required | Meaning |
|---|---|---|
| `<input-id>__<preset-id>.mp4` | yes | e.g. `alley__dolly-in.mp4`. `<input-id>` must exist in `examples/inputs/` (`alley`, `forest-cabin`, `retro-diner`, `coast-lighthouse`, ...), `<preset-id>` in `presets/`. A plain name is also what the Demo engine replays |
| `<input-id>__<preset-id>__<variant>.mp4` | yes (variant clips) | Gallery-only clip, never replayed by the Demo engine, e.g. `forest-cabin__fpv-drone__router-minimax-h3.mp4` |
| `<same name>.json` | recommended | Notes by the person who ran it. Copy `_notes.example.json` |
| `<same name>.recipe.json` | written by the importer | Don't create by hand |

Then run:

```bash
.venv/bin/python scripts/import_real.py            # validates, probes, shrinks to <= 6 MB H.264 if needed, writes recipes
```

(or pass paths: `scripts/import_real.py ~/Downloads/alley__dolly-in.mp4`). The gallery lists the clips with a green badge naming the real model and platform (for example **Real MiniMax H3 output via Comfy Router**), best-rated first. How the LTX clips were produced: [`docs/REAL_RUN.md`](../../docs/REAL_RUN.md).

Large originals are kept in `_originals/` (git-ignored). Never rename a simulated file into this folder.
