# examples/real: REAL model outputs

This folder holds **real** clips (generated by a model, not by `app/vcam.py`): currently `alley__dolly-in.mp4` and `alley__crane-up.mp4`, real LTX-2.3 output from Comfy Cloud, **prompt-only (no camera LoRA), unedited**, with the prompts, settings and an honest verdict in the sibling `.json` / `.recipe.json`. The crane clip is only partial (it rises but also pushes forward). Everything else under `examples/` is a labelled simulation (see `../CREDITS.md`).

## What to drop here

| File | Required | Meaning |
|---|---|---|
| `<input-id>__<preset-id>.mp4` | yes | e.g. `alley__dolly-in.mp4`. `<input-id>` must exist in `examples/inputs/` (`alley`, ...), `<preset-id>` in `presets/` |
| `<same name>.json` | recommended | Notes by the person who ran it. Copy `_notes.example.json` |
| `<same name>.recipe.json` | written by the importer | Don't create by hand |

Then run:

```bash
.venv/bin/python scripts/import_real.py            # validates, probes, shrinks to <= 6 MB H.264 if needed, writes recipes
```

(or pass paths: `scripts/import_real.py ~/Downloads/alley__dolly-in.mp4`). The gallery lists the clips with a green **Real LTX-2.3 output (Comfy Cloud)** badge, and the Demo engine replays a real clip instead of a simulated one for the same input and move (the progress text says it was generated earlier). How to produce the clips: [`docs/REAL_RUN.md`](../../docs/REAL_RUN.md).

Large originals are kept in `_originals/` (git-ignored). Never rename a simulated file into this folder.
